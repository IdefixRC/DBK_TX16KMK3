First release of this fork, based on v1.0.6.

Two changes need action after updating. Both are described below: assign your model
pictures in Model Setup, and re-enter your pilot name in the widget options.

## Settings moved onto the radio

- The pilot name, the low battery percentage and the interval between low battery alerts are now **widget options**, editable on the radio like every other setting.
- `/WIDGETS/DBK_TX16KMK3_config.json` is gone. Delete it from your SD card; nothing reads it any more.
- **If you set a pilot name in that file, re-enter it in the widget options.** Otherwise the footer shows `Rotorflight`.
- New options: `AlertIntvl`, seconds between repeated low battery alerts, default `10`, and `PilotName`, default `Rotorflight`. `BatAlertPct` is unchanged and still defaults to `25`.
- `PilotName` is an EdgeTX text option, so it holds at most 12 characters.
- Settings no longer reload from the card once a minute; EdgeTX stores them itself and applies changes immediately.

## Model images

- The widget now uses **only** the image you assign to the model in EdgeTX **Model Setup**, loaded from `/IMAGES/`.
- The lookup based on the model name is gone. v1.0.6 first looked for `/IMAGES/<model name>.png`, ignoring a leading `>`, and only then fell back to the Model Setup image.
- **If you relied on the model name lookup, open each model in Model Setup and assign its picture.** Without that the widget shows its built-in default image.
- Model names are now free-form. The `>` prefix convention no longer changes anything.
- The two sample pictures that used to ship in `modelImage/` are no longer part of the package.

## Documentation

- The README and the release notes are in English, as are all comments in the script.
- New troubleshooting section covering two common cases: the flight controller not being detected in DFU mode while flashing, and the widget showing its default picture instead of a model image.

## Installation

- `deploy.sh` is removed. Install by copying the `DBK_TX16KMK3` folder onto the SD card, as described in the README.
- The VS Code deploy task is removed as well.
- The package no longer carries `deploy.sh`, `config.lua`, `README.md` or the `modelImage/` folder. What lands on the card is what the widget actually reads.

## Unchanged

Telemetry display, audio alerts, RGB LED control and the performance work from v1.0.6 all behave exactly as before.
